## 2024-05-24 - Interactive Container Accessibility
**Learning:** Large container elements, such as task items or cards, that act as click targets must be fully keyboard accessible. Adding just `onClick` excludes keyboard users. However, when making the container a button (using `role="button"`, `tabIndex={0}`, and `onKeyDown`), any nested visual icons that previously acted as buttons must have their semantics removed (e.g., using `aria-hidden="true"` and changing tags from `<button>` to `<div>`). This prevents nested interactive element issues and confusing screen reader experiences.
**Action:** When implementing clickable large areas, I will ensure the container has complete keyboard support (`role`, `tabIndex`, `onKeyDown`, focus styles) and strip interactivity from internal decorative elements to maintain semantic HTML.
