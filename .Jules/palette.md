## 2024-10-27 - Preserving Large Click Targets with Keyboard Accessibility
**Learning:** When making large container items (like task cards) interactive for better UX (larger click area), simply adding `onClick` makes them inaccessible to keyboard users and screen readers. Furthermore, nesting genuinely interactive elements (like a "Solve" button) inside these containers causes issues with assistive technologies, and visual-only controls (like checkmarks) shouldn't be buttons.
**Action:** Add `role="button"`, `tabIndex={0}`, `aria-pressed` (for toggles), and an `onKeyDown` handler (Enter/Space) to the container. Convert inner decorative buttons to `div` with `aria-hidden="true"`. Use `e.stopPropagation()` on both `onClick` and `onKeyDown` for nested, genuinely interactive child elements.
