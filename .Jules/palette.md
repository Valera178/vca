## 2024-05-09 - Accessible Interactive Containers with Nested Buttons
**Learning:** Making large container `div`s interactive (e.g., for task selection) creates accessibility challenges when they contain nested visual controls or actual buttons (like a "Solve" button). Naively wrapping everything in a single `button` element creates a nested interactive element spec violation. Using a standard `button` for the container and stopping propagation on inner buttons is safer for UX than rebuilding the DOM structure, but requires manually managing `onKeyDown` and focus states for the parent `div`.
**Action:** When making list items interactive, preserve the large click target by making the container a `div` with `role="button"`, `tabIndex={0}`, and an `onKeyDown` handler for Enter/Space. Convert purely visual sub-components (like checkmarks) to non-interactive elements (`div aria-hidden="true"`). For genuinely separate nested actions, use `e.stopPropagation()` on both `onClick` and `onKeyDown` to prevent parent activation.
