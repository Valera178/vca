## 2024-05-10 - Accessible Interactive Cards
**Learning:** When making a large visual container interactive (like a selectable task card) to preserve a large click target, placing a functional `<button>` inside it for visual toggling creates an accessibility violation (nested interactive elements). Screen readers and keyboard navigation may struggle to determine the correct interactive target.
**Action:** Make the container itself the interactive element (`role="button"`, `tabIndex={0}`, `aria-pressed`, `onKeyDown`). Replace the inner visual-only `<button>` with a non-interactive element like `<div aria-hidden="true">`. For genuinely separate nested interactions (e.g., a "Solve" button inside the card), use `e.stopPropagation()` on both click and keydown events to prevent triggering the parent container.
