## 2025-02-12 - Interactive Div Accessibility Pattern
**Learning:** Found a recurring pattern in the app (`StudentCabinet.tsx`, `Syllabus.tsx`) where `div` elements are used as interactive containers (with `onClick`) that often contain nested interactive elements like `<button>`. This creates two issues: 1) the outer `div` lacks keyboard accessibility (`role`, `tabIndex`, `onKeyDown`) causing a poor experience for screen readers and keyboard users, and 2) having a visual-only `<button>` inside an interactive container can confuse screen readers.
**Action:** When making these custom `div` containers accessible, add `role="button"`, `tabIndex={0}`, `onKeyDown` (Space/Enter toggling), and `aria-pressed` (if it's a toggle). Furthermore, change inner visual-only controls (like checkboxes or icons currently implemented as `<button>`) to `<div aria-hidden="true">`, and explicitly prevent event bubbling (`e.stopPropagation()`) on any genuinely separate interactive elements (like a nested "Action" button) to prevent unwanted parent interactions.
