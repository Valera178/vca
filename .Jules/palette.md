## 2024-05-18 - Making Large List Items Keyboard Accessible
**Learning:** Large, visually interactive container elements (like task list items) often use `div` elements to maintain layout flexibility and visual hit-target sizes. However, these are inherently inaccessible to keyboard users and screen readers unless explicitly marked up. The problem is exacerbated when these containers include inner interactive elements (like a nested "Solve" button), which can lead to invalid HTML (buttons inside buttons) or confusing focus flow.
**Action:** When making large container `div`s interactive, assign `role="button"`, `tabIndex={0}`, and appropriate ARIA states (like `aria-pressed`). Crucially, handle both `onClick` and `onKeyDown` (for Enter and Space keys) on the container. Convert purely visual indicators (like custom icon checkboxes) inside the container from `<button>` to `<div aria-hidden="true">` to avoid invalid nested interactive structures. Finally, ensure any genuinely separate interactive children (like nested links or specific action buttons) call `e.stopPropagation()` on both click and keydown events to prevent triggering the parent container's action.
