## 2024-05-24 - Interactive Container Accessibility Patterns
**Learning:** When making large container elements like task cards interactive (e.g., togglable via click), it's crucial to explicitly manage nested interactive states. Screen readers can become confused or misread nested buttons. Additionally, relying solely on `onClick` on a `div` ignores keyboard users.
**Action:** When converting a `div` to be an interactive container: 1) Add `role="button"`, `tabIndex={0}`, and an `onKeyDown` handler (listening for 'Enter' or ' ') to ensure full keyboard navigation and actuation. 2) Provide state context via attributes like `aria-pressed`. 3) Convert any purely visual inner interactive elements (like a simulated checkbox button) into non-interactive elements like `<div aria-hidden="true">` to prevent nested interactive element conflicts. 4) Apply `e.stopPropagation()` on both `onClick` and `onKeyDown` for any genuinely separate nested interactive elements (like an inner action button) to stop them from triggering the container's action.
