## 2024-06-07 - Syllabus Component Accessibility
**Learning:** Found a common pattern in the app where custom interactive elements (like the program accordion items in the Syllabus) were built using `div`s with `onClick` handlers but completely lacked keyboard accessibility (`tabIndex`, `onKeyDown`) and ARIA roles/states. Furthermore, these interactive headers often contain block-level semantic elements like `<h3>`, which means we cannot simply convert them to native `<button>` tags (as HTML5 forbids headings inside buttons).
**Action:** When making custom container components interactive, the correct pattern is to keep the `div` but manually implement all button features: add `role="button"`, `tabIndex={0}`, `aria-expanded` (if it's a toggle), an `onKeyDown` handler for 'Enter' and 'Space', and visible focus styles (`focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-emerald-500`). Always remember to add `aria-hidden="true"` to nested decorative icons.
