
## 2024-05-28 - Nested interactive elements in custom toggles
**Learning:** Creating accessible large list items (e.g., custom task toggles) with interactive nested elements (like action buttons inside the list item) can cause issues with screen readers and keyboard navigation if not handled correctly. Changing visual-only indicators (like checkboxes) to non-interactive elements (`<div aria-hidden="true">`) and applying standard button roles/properties (`role="button"`, `tabIndex`, `aria-pressed`) to the container improves the experience.
**Action:** When creating large custom interactive containers, place `role="button"`, `tabIndex={0}`, `aria-pressed` and keyboard handlers (`onKeyDown` for Enter/Space) on the outermost container. Ensure inner visual controls are non-interactive to prevent nested element issues. For any genuinely separate interactive child elements (like secondary action buttons), strictly use `e.stopPropagation()` for both `onClick` and `onKeyDown` to prevent event bubbling.
