## 2024-05-18 - [Accessible Interactive Task Containers]
**Learning:** In the `StudentCabinet` component, the entire task row acts as an interactive toggle, but was implemented as a generic `div` with an `onClick` handler. This breaks keyboard navigation and screen reader semantics. Also, there was a nested visually-presented "button" (for the checkmark) that should actually be hidden from screen readers to prevent redundant reading. Another nested action button "Решить" would bubble events to the container, accidentally toggling the task completion when interacted with.
**Action:** When making large container items interactive, explicitly give them `role="button"` and `tabIndex={0}`, add `onKeyDown` handlers for Space/Enter, hide internal visual toggles using `aria-hidden="true"`, and use `e.stopPropagation()` on nested actual action buttons so they don't trigger the container's interaction.
