## 2025-06-05 - Handling Interactive Containers with Nested Actions
**Learning:** When making large list items or cards interactive (for a larger click target UX), using `<div onClick={...}>` causes accessibility issues. Attempting to use a standard `<button>` wrapper often fails when the card contains other specific actions (like "Edit" or "Solve" buttons) because nested interactive elements are invalid HTML and confusing for screen readers. Furthermore, the inner visual controls (like a checkbox) shouldn't be actual buttons either if the whole container acts as the toggle.
**Action:** Use a `<div>` wrapper but explicitly make it act as a button by adding `role="button"`, `tabIndex={0}`, `onKeyDown` (handling Enter and Space), and relevant ARIA states like `aria-pressed`. Convert inner visual-only toggles into `<div aria-hidden="true">`. For any genuinely separate interactive children (e.g., nested action buttons), apply `e.stopPropagation()` on both `onClick` and `onKeyDown` to prevent the outer container's events from firing. Always apply `focus-visible` styles to both the container and nested buttons for clear keyboard navigation.
